# Развёртывание: GitHub Pages + один выделенный Google-аккаунт

Apps Script, Google Sheets и закрытый Google Drive размещаются в **одном новом аккаунте, созданном специально для Practicus**. Личный Google-аккаунт пользователя не участвует. Интерфейс остаётся на GitHub Pages. Платные сервисы, отдельный OAuth-клиент и сохранённый refresh token не нужны.

## 1. Подготовьте аккаунт приложения

Зарегистрируйте выделенный аккаунт, включите двухфакторную защиту и настройте восстановление доступа. Используйте отдельный профиль браузера, чтобы не создать ресурсы в личном аккаунте. Пароль Google и токены не нужно передавать в чат.

В этом аккаунте откройте https://script.google.com/ и создайте проект **Practicus**. Доступ редактора предоставляйте только доверенным администраторам: редактор может получить доступ к Script Properties. Студентам и преподавателям доступ к проекту, таблице или папке не выдаётся.

## 2. Вставьте готовые файлы

Комплект находится прямо в [apps-script](../apps-script):

- [Main.gs](../apps-script/Main.gs) — Script-файл Main, может заменить автоматически созданный Code.gs.
- [Core.gs](../apps-script/Core.gs) — Script-файл Core.
- [Bridge.html](../apps-script/Bridge.html) — HTML-файл Bridge.
- [appsscript.json](../apps-script/appsscript.json) — манифест; включите Project Settings → Show appsscript.json manifest file in editor.

Для ручной установки Node.js и сборка не нужны. Создайте файлы в редакторе Apps Script и скопируйте содержимое из репозитория.

Core.gs генерируется из server/. Если меняете серверные исходники, выполните `npm ci` и `npm run build`: обновятся apps-script/Core.gs и dist/apps-script/Core.gs. CI проверяет соответствие готового файла исходникам. Последний успешный workflow также сохраняет комплект как artifact apps-script.

Для clasp: выполните сборку, скопируйте .clasp.json.example в локальный .clasp.json, укажите scriptId, затем `npx @google/clasp login` и `npx @google/clasp push`. При входе выбирайте выделенный аккаунт. rootDir указывает на dist/apps-script. Включите Google Apps Script API в пользовательских настройках Apps Script. .clasp.json не коммитится.

## 3. Включите Google Drive API

Манифест уже содержит разрешение Drive и сервис Google Drive API v3. В редакторе Apps Script проверьте **Services / Сервисы**: Google Drive API, версия **v3**, идентификатор **Drive**. Если сервиса нет, нажмите `+` и добавьте его.

Для облачного проекта, автоматически созданного Apps Script, добавление сервиса обычно активирует API. Если вы сами привязали отдельный стандартный Google Cloud project, дополнительно включите Google Drive API в его консоли. Billing не требуется. Создавать Desktop OAuth client, client secret и refresh token не нужно.

Скрипт получает разрешения владельца при первом запуске. Google-токен используется только на сервере для запросов к Drive и не выдаётся браузеру студента.

## 4. Задайте Script Properties

Откройте Project Settings → Script Properties:

| Свойство | Значение |
|---|---|
| AUTH_SECRET | Не менее 32 случайных байт в base64; не обычный пароль |
| PAGES_ORIGIN | `https://kupryakoff.github.io`, без пути /practicus и завершающего / |
| INIT_ADMIN_LOGIN | Первый логин администратора приложения |
| INIT_ADMIN_PASSWORD | Временный пароль приложения, 10–128 символов; это не пароль Google |
| FILE_UPLOADS_ENABLED | true для приёма работ; false для временного отключения |
| BACKUP_KEEP | Необязательно; 7 последних успешных копий, диапазон 2–30 |
| MAINTENANCE_MODE | false в обычной работе; true на время восстановления |
| FILE_LIMIT_BYTES | Необязательно; по умолчанию 26214400, допускается уменьшение |

**DB_ID и DRIVE_ROOT_ID оставьте отсутствующими**: runInitialSetup создаст книгу и закрытую папку в выделенном аккаунте и сохранит их ID. Для повторной установки с существующими данными можно указать ID уже имеющейся закрытой книги и папки этого же аккаунта. Папка другого владельца отклоняется.

Для генерации AUTH_SECRET на своём компьютере с Node.js:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Альтернатива при установленном OpenSSL: `openssl rand -base64 32`. Секрет хранится только в Script Properties, не в GitHub.

## 5. Выполните runInitialSetup

Сохраните файлы. Вверху редактора рядом с кнопками «Выполнить» / «Отладка» выберите **runInitialSetup** в выпадающем списке и нажмите «Выполнить» (Run). Если список ещё не обновился, сохраните проект и перезагрузите страницу. Подтвердите Google-разрешения **выделенного аккаунта приложения**, включая чтение своего email для проверки права запуска. Функция создаст:

1. Книгу Practicus_DB с нужными листами.
2. Закрытую папку Practicus_Private_Storage в Drive этого же аккаунта.
3. Первого администратора приложения и ежечасный триггер очистки.
4. Закрытую папку Practicus_Metadata_Backups, ежедневный триггер metadataBackup_ и первую резервную копию метаданных.

Она проверит владельца папки и отсутствие публичного/domain-доступа, затем удалит INIT_ADMIN_LOGIN и INIT_ADMIN_PASSWORD из Script Properties. Внутренняя функция setup_ по-прежнему остаётся в коде: имена с подчёркиванием в конце редактор скрывает из списка запуска. Используйте runInitialSetup. Этот видимый запуск проверяет Google-идентичность и запрещён анонимному посетителю Web App; не добавляйте незащищённую публичную обёртку вокруг Core.setup().

Повторный запуск использует сохранённые ID и не сбрасывает пользователей/данные. При ошибке API или прав исправьте настройку и повторите; не публикуйте папку для обхода ошибки.

Проверьте, что книга и папка появились именно в выделенном аккаунте. Все файлы будут принадлежать ему и расходовать его квоту. Место Drive также используют другие сервисы Google; для замены комплектов нужен временный запас сверх пользовательских квот.

## 6. Опубликуйте Web App и подключите интерфейс

Deploy → New deployment → Web app:

- Execute as: **Me** — выделенный аккаунт приложения.
- Who has access: **Anyone / Все**, включая пользователей без Google-входа.

Собственные логины приложения проверяются сервером. Публичная точка входа Web App не открывает Drive. Запрет анонимных Web Apps политикой аккаунта — ограничение, которое нужно проверить на прототипе.

Production URL `/exec` запишите в web/config.js:

```js
window.PRACTICUS_CONFIG = Object.freeze({
  apiUrl: 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec',
  name: 'Practicus',
});
```

Не используйте /dev. В config.js нельзя добавлять ID книги/папки, пароли или токены. После обновления кода Apps Script выбирайте Manage deployments → Edit → **New version**, сохраняя URL. После изменения разрешений подтвердите их заново. Изменение одних Script Properties не требует новой версии кода.

## 7. GitHub Pages

В KUPRYAKOFF/practicus откройте Settings → Pages → Source → **GitHub Actions**, затем Actions → Verify and release Practicus → Run workflow: release_ref=v1.0.0, deploy=true, Workflow from main. Сначала установите ту же версию Apps Script. Push в main теперь только проверяет и собирает код. Подробности — [RELEASE.md](RELEASE.md).

Адрес после публикации: https://kupryakoff.github.io/practicus/. Пока apiUrl пустой, доступна только демонстрация. Workflow публикует dist/site. Google-секретов в исходниках и сборке быть не должно.

## 8. Начало работы

Войдите с временным паролем приложения и смените его. В Настройках проверьте версию сервера, владельца Drive и дату последнего backup. Создайте группы, пользователей и доступ преподавателя. Приём разрешается свойством FILE_UPLOADS_ENABLED=true; старый FILE_TRANSPORT_VERIFIED поддерживается только для совместимости, если новое свойство отсутствует.

По решению владельца проверки загрузок и нагрузки исключены из условий выпуска. Они не заявляются пройденными. Развёртывание проверяет только совпадение версий интерфейса и сервера.

## Импорт из Sheets

В UserIntake заполните обычным текстом full_name, login, role (student/teacher/admin), group_id (ID или точное название группы), subgroup (1/2 для студента). id, status и error оставьте пустыми. Не меняйте заголовки.

В кабинете администратора нажмите Пользователи → «Импорт из Sheets». Обрабатывается до 10 строк за запрос. Скопируйте однократно показанные пароли, исправьте строки error. Открытые пароли в таблице не сохраняются. Потерянный временный пароль заменяется сбросом через интерфейс.

## Очистка и восстановление

housekeeping_ запускается раз в час. Старые поколения недоступны сразу; физическое удаление идёт очередью до 50 объектов за проход. В админке есть «Повторить очистку». Ошибки повторяются. Не удаляйте строки файлов и резервы вручную — они нужны для поиска незавершённых объектов.

Метаданные резервируются ежедневно; бинарные файлы не дублируются. Порядок создания копии, подготовки восстановления в отдельную таблицу и ручного переключения DB_ID описан в [RELEASE.md](RELEASE.md). Автоматического изменения рабочей базы нет.

## Переход со старой схемы

Новая установка не требует прежних DRIVE_CLIENT_ID, DRIVE_CLIENT_SECRET и DRIVE_REFRESH_TOKEN. Если они уже были настроены, удалите их из Script Properties и отзовите ненужное разрешение старого OAuth-приложения. Автоматического переноса файлов между владельцами нет. Для чистой установки создайте проект в выделенном аккаунте и следуйте инструкции выше.
