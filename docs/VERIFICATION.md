# Проверки выпуска 1.0.0

Дата: 21 ноября 2026. Сайт GitHub Pages и config.js доступны по HTTP 200; подключён предоставленный владельцем Apps Script URL. Владелец подтвердил работу установленной версии. Новые backup/restore и механизм выпуска проверены локально и в CI; их код требуется установить в Google по RELEASE.md.

## Автоматические проверки

Проверено **58 автоматических тестов**. Выполняются Node-тесты авторизации, бизнес-правил, репозиториев, резервирования, восстановления и согласованности релиза. Точное число и результат фиксируются в GitHub Actions соответствующего коммита.

Проверены:

- PBKDF2-SHA256 600 000 итераций против независимого Node crypto, Unicode, работа без TextEncoder, нормализация логина, одинаковая ошибка неизвестного/неверного логина, постоянные ограничения входов.
- Сессии, отзыв, блокировка, обязательная смена; роли и подгруппы, запрет чужих файлов/админских методов, черновик и архив.
- Локальные модели квот, поколений, повторов, поздней доработки и ошибок сохранения. Эти unit-тесты не обращаются к Google Drive.
- Метаданные копируются без сессий, токенов и Script Properties. JSON нормализуется перед SHA256.
- Проверка чтением обратно, сохранение старых копий при сбое, ротация, lease параллельных backup и двухфазная фиксация pending → successful.
- Запрет общедоступной папки/файла backup и чтения файла из другой папки до доступа к содержимому.
- Проверка формата, схемы, дубликатов ID, SHA256 и storage root до записи восстановленных данных.
- Восстановление в отдельную таблицу при maintenance, пустые сессии и резервы, сохранение оценок, недоступность отсутствующих/удалённых файлов. Если текущая история удалений недоступна, файлы блокируются.
- Неудачное восстановление не активирует базу. Обычная работа и commit загрузки запрещены при maintenance.
- Backup через интерфейс доступен только администратору. Редакторские функции backup/restore запрещены анонимному или постороннему Google-пользователю.
- Расширение Sheets за пределами начальных 1000 строк для роста аудита и восстановления.
- Публикация интерфейса требует точного релизного тега и совпадения версии/отпечатка Apps Script. Public health выдаёт только идентификатор выпуска.

`npm run check` проверяет синтаксис, JSON, метаданные HTML и список публичных GAS-функций. `npm run build` собирает статический сайт, Core.gs и release manifest; CI проверяет соответствие готового Core.gs исходникам. `npm run package` создаёт два ZIP и SHA256SUMS.

## Браузер

Chromium, desktop 1440×1050 и узкий экран 390×844. **7 сценариев**, без ошибок JS/console:

1. Страница входа учитывает настроенный production endpoint.
2. Поиск, фильтры студента, архив только с оценкой.
3. Возврат работы преподавателем на доработку и показ комментария студенту.
4. Создание/публикация задания, безопасный вывод строки `<script>`.
5. Пользователи, квоты, однократный сброс пароля, доступ преподавателя; настройки и создание виртуальной backup в демо.
6. Тёмная тема, в localStorage только настройка темы.
7. Узкий экран без горизонтального переполнения страницы.

Команда: `SKIP_FILE_TESTS=1 node scripts/browser-check.mjs` при запущенном локальном сервере и установленном Playwright. Браузерные сценарии используют вымышленные данные и не входят в рабочие аккаунты.

## Исключено по решению владельца

Настоящие загрузки/скачивания, проверка предельного объёма и нагрузочные испытания. Не выполнялись и не заявляются успешными; не являются условием выпуска. См. FEASIBILITY.md. Скрипт check-deployment читает только публичные сведения о версии, без передачи учебных файлов.

## Практические пределы

Реальный первый backup и восстановление на Google выполняются владельцем после установки. Секреты и рабочая таблица не передавались и не изменялись инструментами этой подготовки. Копии в том же аккаунте не защищают от потери самого аккаунта. Бинарные файлы не дублируются и физически удалённые работы не восстановятся.

Остаются ограничения бесплатного Apps Script/Drive, чтение небольших Sheets целиком, отсутствие WAF/антивируса, полного редактора ролей, удаления задания целиком и массового скачивания. Аудит в интерфейсе ограничен последними 300 событиями; резервирование включает полный Audit, пока размер снимка не превышает 20 МиБ. При превышении размера фиксируется ошибка без удаления предыдущих копий.
