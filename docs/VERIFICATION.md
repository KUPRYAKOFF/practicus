# Проверки первой версии

Дата: 21 ноября 2026. Локальная среда: Node.js 24, Chromium, Linux. Живого Google-развёртывания нет.

## Выполнено

Исправлен запуск установки: в редакторе выбирается runInitialSetup, поскольку setup_ скрывается из меню. Проверены допуск совпадающей Google-идентичности и отказ анонимному/постороннему вызову до выполнения setup.

`npm test`: **36 / 36**.

- PBKDF2 600 000 итераций сверен с независимым Node crypto, включая кириллицу/emoji. Локальное время около 1 секунды; это **не измерение Apps Script**.
- Вход, нормализация логина, одинаковая ошибка для отсутствующего аккаунта и неверного пароля, постоянные ограничения попыток.
- Сессии: хеш вместо токена в БД, обязательная смена, блокировка, отзыв.
- Границы 25 файлов / 25 МиБ и превышения, MIME/расширения/сигнатуры.
- Подгруппы, чужие группы, чужой преподаватель, скрытые черновики, архив с одной оценкой.
- Время начала, граница дедлайна, доработка после закрытия.
- Резервы квот, повторный ключ, дубль формы, конфликт поколения проверки.
- Сбой в середине замены сохраняет прежние файлы/оценку; успешная замена сбрасывает оценку и повышает попытку.
- Повторная проверка квоты, сессии, аудитории и решения перед commit.
- Потеря ответа после commit: восстановление по поколению.
- Удаление pending-файлов и двухлетняя очистка сохраняют оценку; ошибки физического удаления повторяются.
- В production загрузки заблокированы до проверки транспорта; admin-spike доступен.
- Единый аккаунт: папка создаётся однократно, повторный setup использует её ID; Drive-запросы используют только серверный токен владельца Apps Script; чужая или публичная папка отклоняется. Загрузка, диапазоны и удаление проверены на HTTP-моках без сохранённого refresh token.

`npm run check`: синтаксис JS, JSON, метаданные HTML и список публичных функций GAS — успешно.

`npm run build`: статический сайт и Core.gs — успешно. Готовый apps-script/Core.gs включён в репозиторий; CI проверяет его соответствие исходникам.

Браузер: **8 / 8 сценариев Chromium**, ошибок JS и console errors нет:

1. Вход и явно отключённый неподключённый production-login.
2. Студенческие фильтры, поиск, архив только с оценкой.
3. Реальный File input в демонстрации, отправка, подтверждение замены, исчезновение старого файла и скачивание нового.
4. Преподаватель возвращает на доработку, студент видит комментарий.
5. Создание и публикация задания; `<script>` отображается как текст.
6. Администратор создаёт пользователя, меняет квоту, сбрасывает пароль с однократным показом и отзывает доступ к группе.
7. Тёмная тема; в localStorage только ключ темы, без учётных данных.
8. Экран 390×844 без горизонтального переполнения страницы, переход в задание.

Просмотрены скриншоты кабинета студента и страницы задания в desktop/mobile. Браузерные проверки выполнены на **демонстрационном адаптере**, не на Apps Script API.

Для повторения UI-тестов запустите `npm run serve`; в окружении с установленным Playwright:

```sh
node scripts/browser-check.mjs
```

При необходимости задайте `PLAYWRIGHT_MODULE` (путь к установленному модулю) и `BROWSER_EXECUTABLE` (путь к Chromium). Скрипт не устанавливает браузер автоматически. Скриншоты и JSON-отчёт записываются в игнорируемый `work/`.

## Не выполнено и ограничения

- Приватная передача 1–25 МиБ через настоящий GitHub Pages → iframe HTML Service → Apps Script → Drive выделенного аккаунта **не проверена**.
- Работа iframe при различных настройках сторонних cookies/Google-входа, Firefox и реальное время PBKDF2 на Apps Script не проверены.
- 30 одновременных клиентов, реальные Google квоты/время блокировок и загрузка ≤120 секунд не проверены. Симуляция резервов в unit-тесте не является нагрузочным испытанием.
- Реальная отправка Blob в HTML-форме, Drive resumable HTTP и авторизованные диапазоны скачивания требуют отдельной приёмки. Смотрите FEASIBILITY.md.
- Создание выделенного аккаунта, подтверждение разрешений Drive и публикация Web App требуют действий его владельца. Пароль Google и токены не должны передаваться в чат.
- Предельный размер задаётся Script Properties и может быть уменьшен в рамках требования бесплатности после испытаний. Публичного обхода нет.
- Старые поколения закрываются логически сразу, а физически удаляются очередью до 50 объектов за один проход; по умолчанию раз в час. При ошибках/большом хвосте время увеличивается. В админке доступен ручной повтор очистки.
- В v0.1 нет полного редактора ролей/профилей, пакетного скачивания, удаления всего задания, богатого HTML-редактора инструкций, автоматической миграции схемы или автоматизированного восстановления бэкапа. Создание ролей, изменение статуса/группы/квоты и архивирование реализованы.
- БД и audit читаются целыми небольшими листами. Это первая реализация для порядка 100 аккаунтов, а не гарантия масштабирования.
- В UI аудит ограничен последними 300 событиями; полный журнал остаётся в Sheets. Автоматическое удаление исторических метаданных и оценок не выполняется.
- Глобальное ограничение входов не защищает Google runtime от всех DoS-атак. Нет внешней WAF/CAPTCHA, антивируса и проверки внутреннего содержимого ZIP/Office. Файлы не исполняются приложением.
- Автоматические резервные копии бинарных файлов не создаются; ручная закрытая копия Sheets не восстанавливает физически удалённые файлы. Проверка восстановления на Google не выполнена.

Рабочий релиз с реальными учебными файлами не принят до выполнения протокола FEASIBILITY.md. Интерфейс в demo-режиме пригоден для знакомства и согласования первой версии.
