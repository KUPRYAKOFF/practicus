# Practicus 1.0.0

Система сдачи практических работ: студент, преподаватель, администратор. Интерфейс — **GitHub Pages**, метаданные и сервер — **Google Sheets / Apps Script выделенного аккаунта приложения**, файлы — **закрытый Google Drive того же аккаунта**. Платных сервисов и подписок в проекте нет.

**Статус:** пользователь подтвердил работу опубликованного приложения. Выпуск 1.0.0 добавляет ежедневное резервирование метаданных, безопасную подготовку восстановления и управляемую публикацию пар Apps Script / интерфейс. Проверки загрузок и нагрузки исключены по решению владельца. Новые возможности нужно установить в Google по [инструкции обновления](docs/RELEASE.md).

## Быстрый просмотр

После включения Pages: `https://kupryakoff.github.io/practicus/`.

- `?demo=student` — кабинет студента;
- `?demo=teacher` — кабинет преподавателя;
- `?demo=admin` — кабинет администратора.

Данные вымышлены. Изменения и выбранные файлы хранятся в памяти вкладки до перезагрузки. В браузере сохраняется только тема. Вход в реальную систему включается после заполнения публичного `web/config.js` адресом Web App `/exec`.

## Что реализовано

- Светлая/тёмная темы, адаптация к узкому экрану, поиск, фильтры и сортировка заданий.
- Создание заданий, несколько групп/подгрупп, черновик, публикация, архив, материалы преподавателя.
- Комплекты до 25 файлов / 25 МиБ, проверка размера, расширения, MIME и базовых сигнатур.
- Сдача, безопасная замена целого комплекта, квоты 125/250 МиБ, резервирование, ключи повторного запроса, проверка поколения.
- Реестр студентов, включая несдавших, скачивание отдельных файлов, необязательные оценка 2–5 и комментарий, доработка после дедлайна.
- Базовые пользователи, группы, права преподавателей, блокировка, сброс пароля, квоты, отзыв сессий, аудит.
- Импорт пользователей из `UserIntake` через администратора; временные пароли показываются однократно.
- Собственная авторизация: PBKDF2-HMAC-SHA256, 600 000 итераций, уникальные соли; токен в памяти вкладки, в Sheets только его хеш; сессия 8 часов.
- Закрытый Drive через серверные разрешения Apps Script выделенного аккаунта, порционное авторизованное скачивание без публичных ссылок и owner-токенов в браузере.
- Ежедневные закрытые копии метаданных с SHA256, 7 успешных снимков, состояние копий в админке и восстановление в отдельную таблицу.
- Управляемый выпуск из тега с проверкой версии и отпечатка сервера; обычный push не меняет рабочий сайт.
- Очистка старых поколений, незавершённых загрузок и файлов старше двух лет, очередь повторного удаления. Оценки сохраняются.

## Локальная разработка

Нужен Node.js 20.19+ (проверено на Node 24).

```sh
npm ci
npm test
npm run check
npm run build
npm run serve
```

Просмотр: `http://localhost:4173/`. Сборка создаёт:

```text
dist/site/          # только публичный интерфейс для Pages
dist/apps-script/   # готовые файлы Apps Script, включая Core.gs
```

При изменении серверного кода собирайте проект заново. В Apps Script загружается `dist/apps-script`, а не исходные ES-модули из `server/`.

## Развёртывание

Пошаговая инструкция: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). В репозитории не должно быть Google-токенов, временных паролей, ID реальной таблицы или папки. Готовый `Core.gs` находится прямо в [apps-script/Core.gs](apps-script/Core.gs); обновляется командой сборки.

1. В GitHub → Settings → Pages выбрать **GitHub Actions**. Workflow проверяет код и собирает интерфейс. Публикация выполняется отдельно для выбранного релизного тега после обновления Apps Script. Он также сохраняет готовый комплект Apps Script в artifact `apps-script`.
2. Зарегистрировать отдельный Google-аккаунт приложения. В нём создать проект Apps Script и загрузить четыре готовых файла из `apps-script/`.
3. Добавить сервис Google Drive API v3 и подтвердить разрешения скрипта. `runInitialSetup` создаст таблицу и закрытую папку в этом же аккаунте. Отдельный OAuth-клиент не нужен.
4. Настроить Script Properties, выполнить `runInitialSetup`, опубликовать Web App от имени выделенного аккаунта с доступом «Все», вписать `/exec` в `web/config.js`.
5. Задать `FILE_UPLOADS_ENABLED=true` и выпустить тег через workflow по [инструкции](docs/RELEASE.md). Файловые испытания не требуются по решению владельца; [зафиксированное решение](docs/FEASIBILITY.md).

Пароль Google и токены не нужно передавать в чат. Личный Google-аккаунт пользователя в этой схеме не участвует.
