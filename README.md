# Practicus · первая версия

Система сдачи практических работ: студент, преподаватель, администратор. Интерфейс — **GitHub Pages**, метаданные и сервер — **Google Sheets / Apps Script основного аккаунта**, файлы — **закрытый Google Drive другого аккаунта**. Платных сервисов и подписок в проекте нет.

**Статус:** реализованы интерфейс, демонстрационный режим, серверная логика и комплект развёртывания. Реальное развёртывание Google и испытания файлового транспорта ещё необходимы. Рабочие загрузки по умолчанию заблокированы до проверки. Демонстрация не обращается к Google и не доказывает работоспособность транспорта.

## Быстрый просмотр

После включения Pages: `https://kupryakoff.github.io/practicus/`.

- `?demo=student` — кабинет студента;
- `?demo=teacher` — кабинет преподавателя;
- `?demo=admin` — кабинет администратора.

Данные вымышлены. Изменения и выбранные файлы хранятся в памяти вкладки до перезагрузки. В браузере сохраняется только тема. Вход в реальную систему включается после заполнения публичного `web/config.js` адресом Web App `/exec`.

## Что реализовано

- Светлая/тёмная темы, адаптация к узкому экрану, поиск, фильтры и сортировка заданий.
- Создание заданий, несколько групп/подгрупп, черновик, публикация, архив, материалы преподавателя.
- Комплекты до 25 файлов / 25 МиБ, проверка размера, расширения, MIME и базовых сигнатур.
- Сдача, безопасная замена целого комплекта, квоты 125/250 МиБ, резервирование, ключи повторного запроса, проверка поколения.
- Реестр студентов, включая несдавших, скачивание отдельных файлов, необязательные оценка 2–5 и комментарий, доработка после дедлайна.
- Базовые пользователи, группы, права преподавателей, блокировка, сброс пароля, квоты, отзыв сессий, аудит.
- Импорт пользователей из `UserIntake` через администратора; временные пароли показываются однократно.
- Собственная авторизация: PBKDF2-HMAC-SHA256, 600 000 итераций, уникальные соли; токен в памяти вкладки, в Sheets только его хеш; сессия 8 часов.
- Закрытый Drive через OAuth второго аккаунта, порционное авторизованное скачивание без публичных ссылок и owner-токенов в браузере.
- Очистка старых поколений, незавершённых загрузок и файлов старше двух лет, очередь повторного удаления. Оценки сохраняются.

## Локальная разработка

Нужен Node.js 20.19+ (проверено на Node 24).

```sh
npm ci
npm test
npm run check
npm run build
npm run serve
```

Просмотр: `http://localhost:4173/`. Сборка создаёт:

```text
dist/site/          # только публичный интерфейс для Pages
dist/apps-script/   # готовые файлы Apps Script, включая Core.gs
```

При изменении серверного кода собирайте проект заново. В Apps Script загружается `dist/apps-script`, а не исходные ES-модули из `server/`.

## Развёртывание

Пошаговая инструкция: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). В репозитории не должно быть OAuth-клиента, refresh token, временных паролей, ID реальной таблицы или папки.

1. В GitHub → Settings → Pages выбрать **GitHub Actions**. Workflow проверяет код, собирает интерфейс и публикует Pages. Он также сохраняет готовый комплект Apps Script в artifact `apps-script`.
2. В основном Google-аккаунте создать проект Apps Script и загрузить комплект.
3. В другом аккаунте выдать серверу OAuth-доступ `drive.file`; помощник создаёт закрытую папку именно от имени хранилища. Простое расшаривание папки не переносит расход квоты на другой аккаунт.
4. Настроить Script Properties, выполнить `setup_`, опубликовать Web App от своего имени с доступом «Все», вписать `/exec` в `web/config.js`.
5. Пройти [протокол испытаний](docs/FEASIBILITY.md). Только после успеха выставить `FILE_TRANSPORT_VERIFIED=true`.

Google-пароли, refresh token и client secret не нужно передавать в чат.
